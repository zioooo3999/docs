## Overview

The **Collection Types Permissions** setting allows administrators to configure granular access rights for a specific role across various repeatable content structures in the CMS (such as _Activity_, _Attraction_, or _Event_).

By toggling specific actions—like creating, reading, updating, deleting, or publishing—for each collection type, administrators can enforce strict access control and ensure users only interact with content relevant to their responsibilities.

## Permission Configuration Matrix

| Action / Column | Function & Description |
| :-- | :-- |
| **Category Selection** | Switch between tabs (**Collection Types**, **Single Types**, **Plugins**, **Settings**) to configure distinct permission areas. |
| **Select All (Module)** | Tick the checkbox next to a content module name (e.g., _Activity_, _Attraction_) to select all permissions for that specific type. |
| **CREATE** | Grants authority to add new data entries for the respective collection type. |
| **READ** | Permits users to view existing data entries in the CMS table and detail views. |
| **UPDATE** | Enables users to edit, modify, or update existing data entries. |
| **DELETE** | Grants authority to permanently remove entries from the system. |
| **PUBLISH** | Allows users to publish or unpublish entries directly to the live website. |

---

## How to Configure Permissions

1. **Select Permission Category:** Click on the **Collection Types** tab (or switch between _Single Types_, _Plugins_, or _Settings_) to target the specific permission scope.
2. **Set Module-Wide Access:** Tick the checkbox next to a content module name to grant full permissions (_Create_, _Read_, _Update_, _Delete_, _Publish_) instantly.
3. **Set Granular Controls:** Customize access by checking or unchecking individual action columns (**CREATE**, **READ**, **UPDATE**, **DELETE**, **PUBLISH**) per content type.
4. **Save Configuration:** Save the role settings to apply the updated permission matrix across all assigned accounts.

---

<Note>
  **Security Recommendation:** Restrict the **DELETE** and **PUBLISH** capabilities to trusted roles (such as _Editor_ or _Super Admin_) to prevent unauthorized content removals or unvetted updates from going live.
</Note>
