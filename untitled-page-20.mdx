## Prerequisites

Before starting the installation, make sure the target environment meets the following technical requirements:

| Component | Requirement | Note |
| :-- | :-- | :-- |
| **Node.js** | Version `≥ 20` and `≤ 24` | Required for both backend and frontend environments. |
| **Package Manager** | `npm` | Bundled with Node.js. |
| **Database** | PostgreSQL 16 | Primary relational database engine. |
| **Object Storage** | MinIO / S3-compatible | Used for persistent media upload storage. |
| **Web Server** | Nginx _(Optional)_ | Recommended as a reverse proxy for SSL & domain routing. |

## Backend Installation (Strapi)

<Steps>
  <Step title="Repository Setup & Dependencies">
    Clone the backend repository, checkout the active `develop` branch, install dependencies, and create the local environment file:

    ```bash
    git clone [repo-web-be]
    cd web-be
    git checkout develop
    npm install
    cp .env.example .env
    ```

    <Note>
      Fill in the `.env` file according to the system Configuration Guide before proceeding to database setup.
    </Note>
  </Step>
  <Step title="Database Provisioning & Data Restoration">
    Prepare the PostgreSQL database with `strapi` as the owner and restore the delivered dump file:

    ```bash
    createdb tempepark
    pg_restore --no-owner --role=strapi -d tempepark tempepark.dump
    ```

    <Warning>
      The delivered `tempepark.dump` file is in PostgreSQL custom format and **must** be restored using `pg_restore`, not standard SQL import scripts (`mysql <`).
    </Warning>
  </Step>
  <Step title="Run Application Server">
    - **Development Mode:** Starts local development server with hot-reloading at [http://localhost:1337](http://localhost:1337):
      ```bash
      npm run develop
      ```
    - **Production Build:** Builds administrative panel assets and launches the production server:
      ```bash
      npm run build
      npm run start
      ```
  </Step>
</Steps>

## Frontend Installation (Next.js)

<Steps>
  <Step title="Repository Setup & Configuration">
    Clone the frontend repository, switch to `develop`, install packages, and initialize local configuration:

    ```bash
    git clone [repo-web-fe]
    cd web-fe
    git checkout develop
    npm install
    cp .env.example .env.local
    ```

    Configure the API endpoint and authorization token inside `.env.local`:

    - `NEXT_PUBLIC_STRAPI_URL`
    - `STRAPI_API_TOKEN`
  </Step>
  <Step title="Run Application Server">
    - **Development Mode:** Runs local web application at [http://localhost:3000](http://localhost:3000):
      ```bash
      npm run dev
      ```
    - **Production Build:** Compiles optimized production build and starts application:
      ```bash
      npm run build
      npm run start
      ```
  </Step>
</Steps>

## Database Migration Strategy

The database schema is fully managed by **Strapi**.

For a fresh server using delivered data, simply restore the PostgreSQL dump as outlined in the backend setup. Strapi applies its own internal schema migrations automatically upon application boot, requiring **no additional manual migration steps**.

## Installation Verification

Confirm that services are functioning properly by verifying the following health checks:

<CardGroup cols={2}>
  <Card title="Admin Dashboard" color="#10b981" icon="desktop">
    `GET [cms-url]/admin` returns **HTTP 200** and loads admin UI.
  </Card>

  <Card title="Public API Endpoint" color="#38bdf8" icon="globe">
    `GET [cms-url]/api/pages` returns **HTTP 200**.
  </Card>

  <Card title="Protected API Endpoint" color="#f59e0b" icon="lock">
    `GET [cms-url]/api/attractions` with `Bearer [token]` header returns **HTTP 200**.
  </Card>

  <Card title="Frontend Application" color="#6366f1" icon="browser">
    Next.js application renders pages correctly in modern browsers.
  </Card>
</CardGroup>

### Verification Commands

Execute the following `curl` verification checks to validate API accessibility:

```bash
# 1. Admin Panel Check
curl -i [cms-url]/admin

# 2. Public Route Verification
curl -i [cms-url]/api/pages

# 3. Authenticated Bearer Token Verification
curl -i -H "Authorization: Bearer [token]" [cms-url]/api/attractions
```
