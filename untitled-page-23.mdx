## Overview

This guide details essential operational procedures and maintenance routines required to maintain the stability, performance, and security of the Tempe Park infrastructure.

---

## 1. Docker Management

Routine container management and maintenance tasks are executed using standard Docker CLI commands.

<Tabs>
  <Tab title="Container Operations">
    ### Container Status & Lifecycle

    Monitor active containers or perform service restarts when applying updates or resolving performance bottlenecks:

    ```bash
    # View active containers and status
    docker ps
    
    # Restart a specific container by name
    docker restart [container_name]
    
    # Pull latest images and recreate containers in background
    docker compose pull && docker compose up -d
    ```
  </Tab>
  <Tab title="Cleanup & Pruning">
    ### Resource Cleanup

    Periodically clear unused resources to maintain host disk capacity:

    ```bash
    # Remove dangling and unused images safely
    docker image prune
    ```

    <Warning>
      **Use `docker system prune` with extreme caution.** It removes all stopped containers, unused networks, and dangling volumes, which may contain critical persistent data if not properly mapped.
    </Warning>

    ```bash
    # Advanced cleanup (clears unused networks, volumes, and containers)
    docker system prune
    ```
  </Tab>
</Tabs>

## 2. Storage & Critical Assets

Media assets are stored within the dedicated MinIO bucket `tempe-park`. Regularly check host disk usage to prevent system crashes due to low storage capacity.

```bash
# Check host system disk space availability
df -h
```

<Note>
  Bucket usage and object limits can be monitored directly via the **MinIO Console** dashboard or through the MinIO metrics endpoint.
</Note>

<Warning>
  ### Critical Persistent Data — Do Not Delete

  Under **no circumstances** should any administrator or script remove:

  1. The contents of the **MinIO object storage bucket** (`tempe-park`).
  2. The **PostgreSQL data directory** on the database host.
  3. Active production **`.env` files** across the application directories.
</Warning>

## 3. Log Management & Troubleshooting

When diagnosing errors or downtime, inspect log files in a top-down order (Application Layer $$\rightarrow$$ Web Server Layer).

<AccordionGroup>
  <Accordion title="Application Logs (Strapi & Next.js)" icon="terminal">
    Inspect live process streams and application errors using your active supervisor or container engine:

    ```bash
    # PM2 log stream
    pm2 logs
    
    # Docker container logs
    docker logs -f [container_name]
    
    # Systemd / Journalctl logs
    journalctl -u [service_name] -f
    ```
  </Accordion>

  <Accordion title="Web Server Logs (Nginx)" icon="globe">
    Nginx logs capture routing errors, SSL failures, proxy timeouts, and client requests:

    - **Access Log:** `/var/log/nginx/access.log`
    - **Error Log:** `/var/log/nginx/error.log`

    ```bash
    # Tail web server error logs in real time
    tail -f /var/log/nginx/error.log
    ```
  </Accordion>
</AccordionGroup>

## 4. Basic Health Check Flow

If the platform becomes unreachable, run diagnostics sequentially in the following priority order:

```text
[1. Docker Containers] ➔ [2. Nginx Web Server] ➔ [3. PostgreSQL DB] ➔ [4. MinIO Storage] ➔ [5. Host Disk Capacity]
```

| Order | Component | Diagnostic Focus |
| :-: | :-- | :-- |
| **1** | **Docker Containers** | Verify if application containers (Strapi/Next.js) are active (`docker ps`). |
| **2** | **Nginx Web Server** | Confirm Nginx service status and check for reverse proxy errors (502/504). |
| **3** | **PostgreSQL Database** | Validate connection status, port `5432` availability, and active pool limits. |
| **4** | **MinIO Storage** | Ensure storage service is online and S3 endpoints respond to API calls. |
| **5** | **Disk Capacity** | Verify that host root and volume partitions have sufficient space (`df -h`). |

## 5. Patching & Update Procedure

Perform system maintenance during designated low-traffic maintenance windows to minimize disruption.

<Steps>
  <Step title="System Backup">
    Create comprehensive backups prior to applying any updates or OS patches:

    - Export a PostgreSQL database snapshot.
    - Backup the codebase and configuration `.env` files.
    - Ensure MinIO bucket state is preserved.
  </Step>
  <Step title="Apply Updates">
    Execute required software updates across application source code, Docker base images, OS packages, and npm dependencies.
  </Step>
  <Step title="System Verification">
    Verify operational health across services. Run health checks to validate API routes and frontend page rendering.
  </Step>
  <Step title="Rollback Contingency">
    If critical errors occur post-update, immediately initiate the system rollback procedure to restore the last verified backup state.
  </Step>
</Steps>
